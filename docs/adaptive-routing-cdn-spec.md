# 普通代理自动择优与 CDN 备用入口验收

基线：main `513fd4f9522ef0968e8fac06803e1db9ffdc9807`。用户已授权实现、测试、合并 main 和部署 VPS-A。

## 行为

- 完整订阅保持普通代理、AI 代理、未分类流量三个主入口。普通代理默认使用自动择优，候选保留 TCP 与 UDP。UDP 不可达时通过客户端健康检查选择可用 TCP，不泄漏到 DIRECT；仍可手动选择故障回退、TCP 或具体节点。
- AI 固定主机、候选协议、稳定选择、住宅出口边界和现有连接保持不变。普通代理择优和回退不能改变 AI 会话的出口。
- 测速应反映完整连接建立的成本，并保留切换容差；不根据单次测量将所有用户固定到一种协议。
- 服务端检测只作诊断证据，不以缺失、过期或异地的 UDP 健康记录删除客户端自动候选；实际客户端健康检查决定是否可用。
- 原有节点参数、用户凭据、端口、计量、订阅链接、国内分流和 DNS 策略保持不变。
- CDN 仍使用动态 Cloudflare DNS、正确 SNI/Host 和有效证书验证。先重现超时所在阶段；只有同条件下重复数据传输及长连接验收通过，才发布修复。不能以其他节点代替 CDN 验收，也不能通过放大超时掩盖失败。

## 已授权的测试接口

1. 公开订阅导出：sing-box、Mihomo、Mihomo Modern、Egern 完整配置的有效引用、三个主组和默认选择；节点配置和 AI 行为兼容性。
2. 原生客户端回环传输：真实请求确认低延迟协议被选中、UDP 失效后 TCP 接管、全部失效时不直连；AI 出口及持续连接不受普通组变化影响。
3. 公网隔离客户端：使用实际线上节点验证 X、Google、ChatGPT；区分认证响应与登录成功、入口页面与完整应用体验。
4. CDN 分段与数据路径：客户端到边缘的 TCP/TLS/WS、源站对照、真实用户认证和计量、70 秒空闲后继续传输。
5. 生产前后检查：服务状态/PID/InvocationID、保护配置哈希、数据库完整性、六种订阅和每个现有协议节点。仅发布通过资格验证的 main 提交，保留回滚记录。

原生 App、iPhone、移动网络及已登录的 X 信息流/视频若未实测，必须标明待验收。飞书不在本次修复范围。
